# V3：电动卡车 + 无人机 + 充电站 + 时间窗

## 1. 动机

W8 的 LNS 与多无人机结果全部建立在 FSTSP 评估器上：卡车续航无限、没有时间窗，约束只有无人机续航与会合。这条局限现在补上——把 week06 的**电动车电池 + 充电站 + 时间窗**叠回卡车-无人机模型。

## 2. 模型与实现

- **电动卡车**：电池容量 Q、每单位距离耗电 ρ；电量不足时绕行到最近充电站满充（耗时 RECHARGE）。为与 week06 的 V1 基线一致，采用同样的假设：卡车总能开到最近充电站，只有"满电仍走不完一段"才判能量不可行。
- **时间窗**：到达早于窗口则等待，晚于窗口记一次违例。
- **无人机**：仍受续航限制，必须由卡车在后续节点回收（会合等待）。
- **关键设计**：路线只列**顾客**（加首尾仓库），充电绕行由评估器在评估时动态插入。这样 week08_lns 的 destroy/repair 可以原样复用，只需换掉评估器。
- **目标**：LNS 用标量目标 `makespan + 1000 × 时间窗违例`，能量不可行直接拒绝；最终报告用完整评估器给出真实 makespan、违例数与充电次数。

对比三档：
- **V1**：纯电动卡车（week06 `truck_ev_route`）——EV 基线
- **V3g**：电动卡车 + 无人机，贪心
- **V3l**：电动卡车 + 无人机，贪心 + LNS

## 4. 结论

- **在电动 + 时间窗设定下，协同收益远大于 FSTSP 设定**：V3l 相对纯电卡车降低 56.7%~87.8%，而同一批方法在 FSTSP 设定（无电池/时间窗）下对 truck-only 的收益约 23%~45%。
- 原因是**无人机卸载缩短了卡车路线，顺带省掉充电绕行并消掉时间窗违例**：V1 平均要充 0.9~2.9 次、违例 2.4~13.5 次；V3l 充电降到 0~1.3 次、违例降到 0~1.0 次。也就是说，电池与时间窗这两个约束**放大了无人机的价值**，而不只是增加难度。
- LNS 在 EV+TW 设定上仍继续加码（相对贪心再降 23.3%~57.3%），与 FSTSP 设定下的结论一致。

## 5. 验证与局限

- **验证**：逐例检查所有顾客都被服务（卡车路线 ∪ 无人机架次 = 全部顾客）、无能量不可行解——通过。
- 局限：V3 目前仍是**单架无人机**（多无人机尚未接到 EV+TW 上）；时间窗在搜索里是罚项而非硬约束（所以允许个别违例，报告里如实给出违例数）；充电是"到站满充"的简化，不支持部分充电。
