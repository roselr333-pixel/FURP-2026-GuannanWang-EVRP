# Schneider (2014) E-VRPTW 复现说明（补充实验）

> 说明：本文件记录我对 Schneider, Stenger & Goeke (2014), *The Electric Vehicle-Routing
> Problem with Time Windows and Recharging Stations*, Transportation Science 48(4) 的 E-VRPTW
> 基准做的**自写构造式复现**。它补在我原有卡车–无人机 EVRP 项目之外，用来展示我也独立实现
> 了带充电站的标准电动车 VRPTW（E-VRPTW）模型，并与文献 BKS 对照。所有数字来自
> `src/experiments/schneider_evrptw.py` 与 `schneider_bks_compare.py`，可一键重跑。
>
> **同一批原始算例文件**也供卡车–无人机模型使用：`std_evrp_instances.make_evrp` 把它们转成
> week-6 的 EVRP-TW 实例格式，`week06_standard_instances.py` 则在真实坐标、时间窗、充电站与电池上
> 重跑 V0/V1/V2 主线（见证据索引 §5c）。

## 1. 模型（E-VRPTW，满充瞬时充电）

- 车队从 depot 出发，服务带时间窗 `[ready, due]` 的顾客，每个顾客服务时间 `serv`。
- 电动车电池容量 `Q`，能耗率 `r`（单位距离耗电），车速 `v`。
- 电池不足时，可绕经最近充电站 **瞬时满充**，补能时间 `= (Q − soc)·g`（`g` 为补能逆率）。
- 容量约束 `C`、时间窗约束（允许到达后等待）、电池非负约束。
- **目标**：Schneider 的层级目标——**先最小化车辆数，再最小化总距离**。

## 2. 实例来源（公开，未用论文 PDF）

- 实例来自公开 GitHub 镜像（EllinorAndRegina 的 ALNS 毕设仓的 `SchneiderEVRPTW/`）。
- 为确认这些文件就是 Schneider 原版，我与 **jmanzolli/E-VRPTW** 仓里的原版实例逐文件核对：
  `c103C5`、`c206C5` 完全一致，`c101C5`、`rc108C5` 仅空白字符差异，数据相同。
  故对标有效。
- 我用到的集合：100 顾客 `_21` 集（21 充电站）、5 顾客 `C5` 集（3–4 充电站）、
  以及 10/15 充电站变体，共 **92 个实例**（已跳过 `readme.txt`）。
- 论文 PDF 本机无法下载（代理拦截学术出版商），但实例为公开数据、模型由实例文件
  底部的参数完全定义，因此复现不依赖 PDF。

## 3. 方法（构造式贪心 + 局部搜索）

`src/experiments/schneider_evrptw.py`：车队为同质车，建模了**多程**——一辆车可服务
多条路线，每次回 depot 后重新装载、按需满充再出发（与 Schneider 2014 的车队设定一致）。
每趟路线按截止时间升序，贪心插入**最近的可行顾客**（容量 / 时间窗 / 电池三重可行；
电池不够则经最近充电站满充后继续）。目标按 Schneider 的层级：先最小化车辆数、再最小化距离。默认 `improve=True` 时，构造结果会再由 `schneider_improve.py` 精化：每趟重新检查并用“最省绕行”的可行充电站修复，整趟可在车辆之间搬移或合并，顾客可 relocate / swap——只有层级目标改善时才接受该步。

**说明**：多程已在模型里开启，但构造式贪心**仍无法全局把顾客分配给多程车辆**——
后发车次出发时刻晚，会错过早时间窗顾客，单辆车实际仍只能跑 1–2 趟。我实测过：
把"每趟顾客数上限"从 ∞ 扫到 3，车辆数始终不降（c201_21 在 14–21 车之间浮动，BKS=4），
距离反而因更多回库而上涨。所以车辆数差距来自**启发式本身**，不是建模缺失。

## 4. 结果

- 92 个实例全部跑通；修掉“新开车辆首趟不检查仓库关闭时间”这个 bug 后，贪心自动把插不进的顾客留给后续趟次，**基线跑里已没有未服务顾客**（`unserved=0`）。
- 18 个实例有 Schneider (2014) 发表的 BKS 可对照（见下表）。BKS 来源：
  - `C5` 小实例（5 顾客）：取自 jmanzolli/E-VRPTW 直接列出的 Schneider (2014) CPLEX 结果；
  - `_21` 大实例（100 顾客）：取自 Adachi et al. (2022, IEICE NOLTA) 引 Schneider (2014) 的 BKS 表。
- **求解时间**：构造阶段每个实例 < 0.02 s；新增的局部搜索在 100 顾客实例上约 7–16 s
  （会收敛；另设每实例预算兜底），92 实例整轮约 14 分钟。差距来自算法质量而非算力。

## 5. 与 BKS 的差距（归因）

**结论：18 个对照实例的平均距离差距降到 +21.3%**（全部完全服务；车辆数 3.28 vs BKS 2.06），
而"只有构造阶段"时是 **+52.7%**。其中 3 个实例（`c208C5`、`r105C5`、`rc208C5`）已与 BKS 完全一致。

| 阶段 | 平均 |距离差距| | 平均车辆数（BKS 2.06） |
|---|---:|---:|
| 构造式贪心（已强制仓库关闭时间） | +52.7% | 5.44 |
| + 局部搜索（整趟搬移/合并、顾客 relocate/swap、2-opt） | **+21.3%** | **3.28** |

求解器是确定的（未分配顾客按 ID 排序迭代），下列数字重跑可精确复现。剩余差距拆分：

| 集合 | 距离差距（均值） | 车辆数（我方 vs BKS） |
|---|---|---|
| C5 小实例（5 顾客） | **+10.1%**（区间 0.0% ~ +27.1%） | 多 0–1 车 |
| `_21` 大实例（100 顾客） | **+43.6%**（区间 +15.5% ~ +97.2%） | 多 2–4 车 |

剩余差距的真实来源（平实陈述，不过度宣称）：

1. **车队装填仍是主要残余**。Schneider 的首要目标是最小化车辆数，其车辆跑多程；我的构造阶段
   一趟一车，局部搜索把大实例从 14–16 车压到 5–9 车，但 BKS 只用 3–4 车，每多一车就多一次
   回仓往返（`c201_21`：6 vs 4；`c206_21`：8 vs 4；`r201_21`：9 vs 3）。
2. **局部搜索只是爬山法**：整趟搬移/合并 + 顾客 relocate/swap + 2-opt，接受规则严格；
   下一步自然是 ruin-and-recreate（ALNS）层。
3. **充电策略仍是"最近站 + 满充"**。部分充电买到的是**时间**，而时间正是限制一辆车能串多少趟的
   因素，因此它是残余车辆差距的下一根杠杆（它不直接改变距离）。

**顺带发现的一个建模 bug**：仓库自己的关闭时间只在"把新趟次接到已有车辆"时检查，新开车辆的第一趟
从未检查，于是 18 个实例里有 3 个（`c103C5`、`r201_21`、`rc201_21`）回到仓库时已经关门。现在
每一趟都强制检查（`build_trip` 会拒绝任何导致超时的顾客）。这让构造基线从 +50.7% 略变差到
+52.7%，但物理上成立；局部搜索随后把损失补回来还多得多。

## 6. 局限与后续任务

- **所有对照实例都完全服务**（这里 18/18；92 实例基线跑里也没有未服务顾客）。
- **全局车队装填仍未解决**：局部搜索能搬移/合并趟次，但初始车队由构造阶段决定，所以 100 顾客实例
  仍比 BKS 多 2–4 辆车。下一根杠杆是 (i) 部分充电（买的是时间，不是距离）与 (ii) 在趟次池上做
  ALNS / ruin-and-recreate。
- 未求精确下界（MILP）；求下界本身是独立贡献，超出本项目范围。
