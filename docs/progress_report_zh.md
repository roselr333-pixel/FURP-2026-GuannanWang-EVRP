## 一、项目要求分析

### 1.1 核心定位

老师在大纲和 README 里反复强调一句话：**目标不是造一个世界级的求解器，而是搭出一套"可复现的研究工作流"**——弄懂一个问题变体 → 跑通一个可靠的基线 → 评估可行性与成本 → 用公平对比验证一个改进。这条主线决定了"做扎实的对比"比"堆算法数量"重要得多。

### 1.2 六项学习目标（完成即达标）

1. 能解释 CVRP、VRPTW、EVRP-TW 和卡车-无人机协同四类问题；
2. 能复现一个基线求解器或学习型策略；
3. 能同时报告目标值、可行性、约束违约和运行时间；
4. 能诊断路线为何不可行或效率低；
5. 能实现一个聚焦改进或约束扩展；
6. 能用清晰证据展示一个可复现的优化实验。

### 1.3 八周计划与阶段交付

| 周次 | 重点 | 该阶段产出 |
|---|---|---|
| 1 | 环境与基线搭建 | 小算例求解记录 |
| 2 | 文献与问题变体 | 阅读笔记 + 约束图 |
| 3 | 复现一个基线 | 目标值、可行性、运行时间日志 |
| 4 | EVRP-TW 约束 | 时间窗与电量违约表 |
| 5 | 卡车-无人机建模 | 建模说明 + 同步规则 |
| 6 | 混合/学习方法 | 小规模算例演示运行 |
| 7 | 改进与消融 | 与基线公平对比 |
| 8 | 最终集成 | 报告、幻灯片、演示视频、可复现材料 |

### 1.4 评分权重（rubric）

- 25% 可复现性与工程质量；
- 25% 基线与改进方法对比质量；
- 20% 失败 / 约束违约分析深度；
- 30% 最终报告、演示、技术解释。

注意其中"最终报告/演示"占三成，而"与基线公平对比"又是另一块两成五——后者恰恰是我之前最薄弱、最近刚补上的一段（见下文 2.2）。

### 1.5 硬性报告标准

指标规范（`benchmarks_metrics`）要求至少：在 3 种规模或 3 个代表性算例上比较基线与改进；同时报告目标值、可行性、运行时间、硬件、随机种子和求解器参数；不能只报"最短距离"；至少 3 个带约束级诊断的失败案例。

### 1.6 我收敛出的研究主线

项目页说"好的 SEP 项目围绕一个聚焦的问题"。我把主线收敛为 **Ground-air collaborative EVRP-TW（地面-空中协同电动车路径）**，研究问题定为：

> 当地面电动车队与无人机协同配送、且两者都受电量与充电约束时，协同策略相比纯地面 EV 车队，能在完工时间（makespan）上带来多少提升？又受哪些约束（无人机航程、时间窗、同步）限制？

所有实验都围绕这个问题展开。

##### GA 5-seed 复核（已完成）

我用 5 个固定种子（`20260717 / 20260801 / 20260815 / 20260901 / 20261001`）把自写 GA 在全部 56 个 Solomon 实例上各跑 5 次，每实例统计均值、最优、种子间标准差，结果落在 `baseline_ga_vrptw_results.csv`（新增 `ga_dist_mean / ga_dist_best / ga_veh_best / ga_gap_mean_pct / ga_gap_std_pct / n_seeds` 六列）。

| 指标（对 BKS 的 gap） | 数值 |
|---|---:|
| 跨实例 seed-均值 gap | **36.6%**（实例间 std 15.8%） |
| 跨实例 best-of-5 gap | **31.2%** |
| 单实例内种子间波动（平均 std） | **3.9 pp** |
| 求解率 | 56/56 可行 |

按算例族分（seed-均值 gap）：C1 25.9%、C2 36.0%、R1 31.2%、R2 41.5%、RC1 30.6%、RC2 56.8%。

**几点说明**：
- 之前报告里写的"约 36.2%"是**单种子**跑出来的，这次 5 种子复核后是 **36.6%**，两者基本一致——说明我的 GA 结果本身比较稳定，单实例内种子波动平均只有 3.9 pp。
- 这不是一个"改进"，只是把已有的自写基线做了统计上更扎实的复核：现在报的是均值±波动，而不是一次随机跑的孤值。best-of-5（31.2%）与均值（36.6%）差约 5 pp，属于 GA 正常的随机差异。
- GA 仍明显弱于 OR-Tools（7.2%），定位不变——它是我自己实现的、用来理解进化算子的基线，不是用来刷 SOTA 的。
- 修了一个之前的隐患：早期版本 `main()` 里在循环外调 `random.seed()` 会污染全局随机源、让"多种子"名不副实；这次改成只在 `solve_ga(seed=...)` 内部按种子重置，五次运行确实相互独立。

### 3.3 方法与科学性可提升

7. ~~**算例规模偏小**~~ ✅ **已部分交付**：`src/experiments/week06_largeN.py` 扩展到 **N=30、N=50**（5 种子），输出 `week06_largeN_summary.csv`。**重要发现**：V2 优势随规模**单调缩小**——

   | 规模 | 之前的 V2 vs V1 | 现在补 |
   |---|---:|---:|
   | N=8  | 50.5% | (沿用) |
   | N=12 | 55.3% | (沿用) |
   | N=16 | 53.9% | (沿用) |
   | N=20 | 42.1% | (沿用) |
   | **N=30** | — | **27.6%** |
   | **N=50** | — | **12.1%** |

   解释：N=50 时 V1（电池+充电）的代价 5670 vs V0（无电池）的 3094——电池约束本身就在 N≥30 时给卡车加了将近一倍代价，而 V2 无人机能"绕开"的充电路径有限，所以协同收益被电池代价稀释。这比单纯的"扩大到 50 客户"更值得讲，因为它把"协同收益随规模衰减"量化了——也是项目页要的"局限性分析"的素材。N=30/50 的 10 个算例可行性 100%，无人机会合约束否决数从 N=20 的 1.5 万跳到 N=50 的 450 万——会合约束在 N=50 真成了主要瓶颈，**这表明同步模型在算例变难时确实成为主要瓶颈**。

8. ~~**贪心无局部搜索**~~ ✅ **已部分交付**：`src/experiments/week07_fstsp_repro.py` 加了 `my_v2_fstsp_with_2opt(inst, max_passes=10)` 函数——对 V2 构造后的卡车路线做 intra-route 2-opt，接受条件是**严格 makespan 改善**。40 算例结果：

   | 规模 | V2 makespan | V2 + 2-opt makespan | 2-opt 增益 | 每算例平均 2-opt 移动次数 |
   |---|---:|---:|---:|---:|
   | N=8  | 236.8 | 235.0 | **+0.90%** | 0.3 |
   | N=12 | 359.3 | 359.3 | **0.00%** | 0.0 |
   | N=16 | 524.6 | 514.3 | **+1.76%** | 0.9 |
   | N=20 | 714.1 | 706.7 | **+0.93%** | 0.3 |

   **结论**：2-opt 给 V2 只带来 0–2% 边际改善。原因：无人机把卡车路线已经缩短成"接近最优"的形态（卸掉了远端客户），剩下的部分几乎已经线性，2-opt 无用武之地。**这是好消息也是坏消息**：好消息是我的 V2 启发式已经接近当前邻域的局部最优；坏消息是"离全局最优多远"仍不可量化（除非加 MILP 上界或更大邻域如 3-opt/or-opt），仍待后续。
