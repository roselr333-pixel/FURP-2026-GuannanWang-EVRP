# 形式化模型：地面-空中协同 EVRP-TW

> 这份文档把我实现的卡车-无人机模型用标准符号写下来，作为报告"问题建模"一节的底稿。
> 写法对齐实际代码：评估器真正检查的约束算硬约束，搜索里当罚项处理的单独标注，
> 没有实现的（例如载重）也明确写出来。

---

## 1. 模型分层

我实现的不是单一模型，而是共用同一套贪心构造核心的几个变体：

| 变体 | 卡车 | 无人机 | 时间窗 | 充电站 | 代码入口 |
|---|---|---|---|---|---|
| V0 | 无限续航（参考下界） | 无 | 计罚 | 无 | `week06_ground_air_evrp_tw.run_variant("V0")` |
| V1 | 电池 + 充电 | 无 | 计罚 | 有 | `run_variant("V1")` |
| V2 | 电池 + 充电 | 单架，每架次 1–2 客户 | 计罚 | 有 | `run_variant("V2")` |
| FSTSP 模式 | 无限续航 | 单架 / K 架，每架次 1–3 客户 | 不考虑 | 无 | `week07_fstsp_repro.fstsp_simulate` |
| V3 | 电池 + 充电 | K 架，每架次 1–2 客户 | 计罚 | 有 | `v3_ev_collab.ev_collab_k` |

V2 与 FSTSP 模式共用同一个完成时间评估器（V2 多一层电量与时间窗）；V3 是把这一层
叠回第 4/6 周的电动车设定。下文的 §2–§5 写主模型（V2 / FSTSP 模式），§6 写各变体的差异。

## 2. 集合与下标

| 符号 | 含义 |
|---|---|
| $0$ | 仓库（depot），路线的起点与终点 |
| $C = \{1,\dots,n\}$ | 客户集合 |
| $S$ | 充电站集合（合成算例中 4 个；FSTSP 模式实例为空集） |
| $V = \{0\} \cup C \cup S$ | 节点集合 |
| $A = \{(a,b) : a,b \in V,\ a \neq b\}$ | 有向弧集合 |
| $C_{\text{truck}}$ | 由卡车服务的客户子集 |
| $T = \{(i_k, C_k, j_k)\}_{k}$ | 架次（sortie）集合：起飞节点 $i_k$、服务客户序列 $C_k$、回收节点 $j_k$ |

$d_{ab}$ 为节点 $a,b$ 之间的欧氏距离。实例几何有两种来源：随机圆形分布（第 6/7 周主线）
与官方 Solomon 拓扑（第 8 周扩展，坐标平移到仓库为原点并按顾客 RMS 半径缩放）。

## 3. 参数

| 符号 | 含义 | 取值 |
|---|---|---|
| $v_T$ | 卡车速度 | 1.0 |
| $v_D$ | 无人机速度 | 2.0 |
| $s_i = s$ | 客户服务时间 | 10 |
| $\chi$ | 充电站满充时间 | 40 |
| $\rho$ | 卡车单位距离耗电 | 1.0 |
| $Q$ | 卡车电池容量 | 250 |
| $R$ | 无人机单架次航程上限 | 160 |
| $m$ | 单架次最多服务的客户数 | 1–3（主线 1–2） |
| $K$ | 无人机数量 | 1（主线）；1–5（第 8 周扩展） |
| $[e_i, l_i]$ | 客户 $i$ 的时间窗 | 合成算例宽度 220；紧窗算例 35 |
| $q_i$ | 客户需求 | 5–15 |
| $\mathrm{CAP}$ | 卡车载重 | 1000（已声明，评估器未启用） |
| $w$ | 多目标权重 | 0, 0.25, 0.5, 0.75, 1.0 |

## 4. 决策变量

- 卡车路线：访问次序，等价地用弧变量 $x_{ab} \in \{0,1\}$ 表示；
- 服务归属：每个客户由卡车还是某个架次服务；
- 架次集合 $T$：每个架次的起飞点 $i_k$、服务客户序列 $C_k$（含顺序）、回收点 $j_k$；
- 无人机分配 $\sigma: T \to \{1,\dots,K\}$（仅 $K > 1$ 时需要）。

---

## 5. 目标与完成时间的递推

目标是**最小化完工时间**（makespan），即卡车带着无人机回到仓库的时刻：

$$\min\ T_{\text{end}} = a_{|\text{route}|}$$

设卡车路线为 $(v_0 = 0, v_1, \dots, v_{L} = 0)$，到达时刻 $a_p$ 由下面递推给出
（$\tau$ 是节点附加时间：客户为 $s$，充电站为 $\chi$，仓库为 0）：

$$a_0 = 0, \qquad a_p = a_{p-1} + \frac{d_{v_{p-1}, v_p}}{v_T} + \tau(v_p)$$

对每个架次 $k$（按起飞节点的路线位置排序）：

$$\lambda_k = a_{\text{pos}(i_k)} \quad(\text{起飞时刻})$$

$$\phi_k = \frac{1}{v_D}\sum_{\ell} d_{\text{leg}_\ell} + s \cdot |C_k| \quad(\text{飞行时间，含逐客户服务})$$

$$r_k = \max\bigl(a_{\text{pos}(j_k)},\ \lambda_k + \phi_k\bigr) \quad(\text{回收时刻})$$

$$w_k = r_k - a_{\text{pos}(j_k)}, \qquad a_p \mathrel{+}= w_k \ \ \forall p \ge \text{pos}(j_k) \quad(\text{卡车在回收点等待})$$

**无人机晚到，卡车就在回收点等它**，等待量顺延到后续所有到达时刻。这是与
Murray & Chu (2015) 一致的会合处理；本项目早期版本把每个架次的降落时刻独立取最大值
（允许一架无人机同时飞两个架次），已在 `docs/analysis/evaluator_physical_fix_note_zh.md` 中修正。

## 6. 约束

### 6.1 硬约束（评估器对违反者返回 $+\infty$）

| 编号 | 约束 | 数学形式 |
|---|---|---|
| C1 | 路线结构：从仓库出发、回到仓库，卡车访问客户至多一次 | $x$ 构成一条 $0 \to 0$ 的路径；$\sum_b x_{cb} = \sum_a x_{ac} = 1 \ \forall c \in C_{\text{truck}}$ |
| C2 | 覆盖：每个客户恰好被卡车或恰好一个架次服务 | $C = C_{\text{truck}} \uplus \biguplus_k C_k$ |
| C3 | 起飞在回收之前（沿卡车行进方向） | $\text{pos}(i_k) < \text{pos}(j_k)$ |
| C4 | 单架次航程不超限 | $\sum_{\ell} d_{\text{leg}_\ell} \le R$ |
| C5 | 单架次客户数 | $1 \le |C_k| \le m$ |
| C6 | 无人机串行：上一架次回收后才能起飞（架次区间不重叠） | $\lambda_k \ge r_{k-1}$；等价地 $\text{pos}(i_k) \ge \text{pos}(j_{k-1})$ 在等待已顺延的到达时刻下成立 |
| C7 | 起飞时无人机必须在卡车上 | $r_{k-1} \le a_{\text{pos}(i_k)}$ |
| C8 | 卡车在回收点等待 | 见 §5 的 $w_k$ |
| C9 | 电量（仅 V1/V2/V3）：两次充电之间电量不为负 | 见 §6.3 |
| C10 | 无人机数量 $K$：每个架次分配一架无人机，各机自身串行；起飞时至少一架空闲 | $\sigma(k) \in \{1..K\}$，$\lambda_k \ge \text{avail}[\sigma(k)]$ |

C6 与 C7 是同一件事的两种说法：**一架无人机同一时刻只能飞一个架次**。这也是 FC-7-4
（嵌套架次）修正后的核心约束。

### 6.2 软约束

| 编号 | 约束 | 处理方式 |
|---|---|---|
| S1 | 客户时间窗 $[e_i, l_i]$ | 早到则等待到 $e_i$；迟到只把违约计数 $+1$，不拒绝解（V1/V2/V3 的 `tw_viol`） |
| S2 | 无人机所服务客户的时间窗 | 启发式在枚举候选架次时用它过滤（`_customer_list_is_feasible`），是搜索设计，不是模型硬约束 |

### 6.3 电量与充电（V1 / V2 / V3）

卡车沿路线耗电 $\rho \cdot d$。当剩余电量不足以驶向下一节点时，采用**贪心充电策略**：

1. 从当前节点绕到**最近的**充电站 $s^\star$，耗时 $d/v_T$；
2. 在该站满充，耗时 $\chi$，电量回到 $Q$；
3. 若满充后仍无法覆盖离开该站的下一段，则标记 $\text{energy\_inf} = \text{true}$，该解视为不可行。

这不是充电站选择的最优化，只是可行性修复。无人机侧只限制单架次航程；回收即视为换电池，
航程逐架次复位。

### 6.4 多目标扩展

`week06_multi_objective.my_v2_weighted` 把插入评分改为加权和：

$$\text{score} = w \cdot (\text{距离节省}) + (1-w) \cdot (\text{makespan 减少量})$$

$w=0$ 复现标准 V2，$w=1$ 只优化距离。这里给出的是加权和标量化的"粗前沿"，不是完整
Pareto 求解器。

## 7. 已实现 / 未实现（写作时要如实交代的）

已实现并进入结果：

- 卡车电量、最近站贪心充电、充电站绕行；
- 客户时间窗（软约束，报告违约数）；
- 无人机单架次航程、逐客户服务时间、回收点会合与卡车等待；
- 单架无人机串行（架次不重叠）；$K$ 架无人机的显式调度；
- 多顾客架次（1–3）与同一停靠点多次起降；
- 小规模精确最优（CP-SAT，$n \le 12$ 规模）。

未建模或明确简化：

- **载重未启用**：参数 $\text{CAP}$ 存在，但评估器与启发式都不检查，$q_i$ 未进入任何约束；
- **无人机能耗与载荷**：只限制航程 $R$，没有电量、载荷对速度/续航的影响；
- **充电策略不做优化**：固定"最近站 + 满充"；
- **时间窗不是硬约束**：主线与 V3 都按罚项计数；
- **充电站只在第 6 周与 V3 的实例中出现**：FSTSP 模式的实例没有充电站，卡车视为无限续航；
- **静态确定性**：服务时间、行驶时间固定，没有随机扰动；
- **每架次客户数上界**：$m \le 3$ 是枚举成本决定的工程上限，不是问题本身的性质。
