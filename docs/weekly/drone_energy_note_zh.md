# 无人机能耗与载荷模型（扩展）

> 写于 2026-09-13。主线里无人机默认的唯一约束是航程常数 `R_D`（单架次飞行距离 ≤ 160），
> 也就是说无人机并不"电动"，而项目本身研究的是电动路径问题。这份说明给它加上真实多旋翼
> 无人机的两个限制——载荷上限，以及随载荷增长的能耗预算——并重跑核心消融，看结论怎么变。

## 1. 模型

- **载荷上限 `P_MAX`**：一个架次携带的客户需求总和不能超过它。
- **能耗预算 `E_D`**：一个架次的能耗为

  $$E = \sum_{\text{段}} (\alpha + \beta \cdot \text{该段仍在机上的载荷}) \times \text{段长}$$

  也就是"货没送完的时候更费电"。
- 参数：`ALPHA = 1.0`、`BETA` 默认 `0.02`、`E_D = 160`、`P_MAX = 30`。
- **`BETA = 0` 且 `E_D = R_D` 时，能耗约束恰好退化为原来的航程约束**：自检用 300 个随机
  计划与 `cpsat_fstsp.fstsp_makespan_clean` 逐值对比，0 处不一致；贪心在 n=8/12 上也
  复现了 `clean_greedy` 的解（卸载的客户集合完全相同）。
- 其余物理语义不变：起飞在回收之前、单架串行（上一架次回收前不能起飞）、卡车在回收点
  等待、不可行返回 `inf`。实现见 `src/experiments/drone_energy.py`。
- **这两个闸门同时装在两个主线评估器上**：`v3_ev_collab.ev_collab_k`（V3：电池、充电、
  时间窗、K 架）与 `week07_fstsp_repro.fstsp_simulate[_multi]`（第 7/8 周）都接受
  `alpha`/`beta`/`ed`/`p_max` 四个参数，默认 `beta = 0`、`ed = R_D`、不限载荷，
  也就是原来的航程模型，所以已提交的数字不变。第 4b 节给出打开闸门后的结果。

## 2. 怎么做的

- 四个配置（cap1 / v2 / notakeoff / cap3）加上已发表的 M&C (2015) 插入启发式；两套实例集：
  合成 40 个（10 种子 × N=8/12/16/20）与标准 Solomon 48 个（4 族 × 3 顾客窗口 × 4 规模），
  与前面的消融用的是同一批实例。
- 三档载荷系数 `BETA` = 0.00 / 0.02 / 0.04。**`BETA = 0` 那一行同时充当与已提交消融的对照**。
- 已发表启发式不感知能耗，它的计划只是被重新评估，所以额外报它的能量可行性比例。

## 3. 结果

各规模均值（完整逐规模表见 `src/results/drone_energy_summary.csv`）：

| 指标 | BETA=0.00 | BETA=0.02 | BETA=0.04 |
|---|---:|---:|---:|
| 多顾客增益（合成，pp） | +10.4 | +8.6 | +6.1 |
| 多顾客增益（标准，pp） | +6.6 | +6.1 | +5.4 |
| 已发表启发式可行性（合成） | 1.00 | 0.62 | 0.42 |
| 已发表启发式可行性（标准） | 0.92 | 0.62 | 0.48 |
| 我的贪心可行性（全部配置、两套实例） | 1.00 | 1.00 | 1.00 |
| v2 卸载客户数（合成 / 标准） | 4.2 / 3.1 | 4.3 / 3.2 | 4.0 / 3.5 |

`BETA = 0` 行与已提交消融的逐项对照：v2 相对 truck-only 为 34.5 / 29.0 / 28.7 / 24.8%
（N=8/12/16/20），多顾客增益 10.6 / 10.2 / 12.1 / 8.6pp，与 `week07_ablation_summary.csv`
完全一致。cap3 略有差别，因为这里的贪心不带 `week07_improvement_ablation` 里的提前剪枝。

图：`figures/drone_energy.png`。

## 4. 结论

1. **载荷/能耗模型把多顾客优势削掉一截，但没有抹掉它**：合成算例从 +10.4pp 降到 +6.1pp
   （约 −41%），标准算例从 +6.6pp 降到 +5.4pp（约 −18%）。方向不变。
2. **cap3 在能耗模型下不再带来增益**：合成算例在三档 BETA 下，cap3 的分解都是
   −0.5 ~ +0.4pp。三顾客架次把载荷推高到能耗惩罚开始咬人的区间，载荷上限也更容易触顶。
3. **是否把能耗写进模型，决定计划可行不可行**：已发表启发式（不感知能耗）的计划在
   BETA = 0.04 时只有 42%（合成）/ 48%（标准）能量可行；我的贪心在每一档 BETA、每个规模上
   都是 100% 可行，因为它在构造候选架次时就检查能耗与载荷。
4. 卸载客户数随 BETA 几乎不变（合成 4.2 → 4.0），但优势明显下降——也就是说，
   载荷惩罚影响的是"多顾客架次值不值"，而不是"无人机还能卸几个客户"。

## 4b. 同一套闸门装到主线的两个设定上

这两个闸门并不只属于上面的消融运行器：`v3_ev_collab.ev_collab_k`（V3：电动卡车、
充电站、时间窗、K 架无人机）与 `week07_fstsp_repro.fstsp_simulate[_multi]`（第 7/8 周
的 FSTSP 评估器）接受同样四个参数，`src/experiments/drone_energy_mainline.py` 就在这两个
设定上把闸门打开。4 个规模 × 10 种子 × K=1/2/3，`beta` = 0.00（对照）与 0.02，
`E_D = 160`、`P_MAX = 30`。

| 模型 | 配置 | BETA = 0.00 | BETA = 0.02 | 变化 | 0.02 下可行率 |
|---|---|---:|---:|---:|---:|
| V3（电动 + 时间窗） | greedy | 643 | 664 | +3.2% | 100% |
| V3 | LNS K=1 | 513 | 521 | +1.5% | 100% |
| V3 | LNS K=2 | 413 | 444 | +7.5% | 100% |
| V3 | LNS K=3 | 361 | 390 | +8.1% | 100% |
| W8（FSTSP） | greedy | 497 | 508 | +2.2% | 100% |
| W8 | LNS K=1 | 407 | 407 | +0.1% | 100% |
| W8 | LNS K=2 | 318 | 334 | +4.8% | 100% |
| W8 | LNS K=3 | 276 | 295 | +7.0% | 100% |

表中是四个规模的平均 makespan（逐规模数值、truck-only 水平与逐实例行见
`src/results/drone_energy_mainline_{raw,summary}.csv`；图 `figures/drone_energy_mainline.png`）。
`BETA = 0` 一列与 `v3_ev_collab_summary.csv`、`week08_multidrone_summary.csv` 逐值一致，
因此它同时是"加参数这次重构"的对照。

1. **闸门的代价是几个百分点，不是结论本身。** 相对 truck-only 的收益几乎不动：V3 K=1 从
   52.4% → 53.0%（N=8）、33.5% → 34.5%（N=20），V3 K=3 从 72.5% → 72.4%、48.3% → 46.0%；
   W8 K=3 从 69.6% → 70.6%（N=8）、54.0% → 51.2%（N=20）。唯一明显变差的是 V3 上单架贪心：
   N=16 时 29.0% → 21.6%——没有改进阶段，它会把载荷压得很重的架次一直留着，之后再付能耗的账。
2. **多出来的无人机少赚了一截。** K=1 → K=3 的缩短幅度在 N = 8/12/16/20 上分别是
   42.1 / 42.2 / 27.2 / 22.3%（仅航程模型），打开闸门后变成 41.3 / 42.4 / 18.6 / 17.1%
   （W8：46.6 / 40.8 / 32.6 / 21.2% → 49.4 / 39.1 / 23.0 / 15.9%）。N ≥ 16 时第三架无人机
   少赚 5–10pp，正是载荷上限与能耗预算开始同时咬人的规模。
3. **我的求解器给出的计划全部仍然可行**（16 个"规模 × 配置"格子全是 100%，K=1 的计划里
   载荷/能耗违例为 0），因为闸门是在构造候选时就检查的。这与第 3 节里不感知能耗的已发表
   启发式形成对照（后者只有 42–48% 的计划能量可行）：把电写进约束代价很小，忽视它代价很大。
4. **卸载客户数基本不变**（V3：K=1 两种情况都是每实例 5.8 个，K=3 从 9.5 → 9.4；W8：K=3
   从 8.5 → 9.2）。与第 4 节一致：闸门改变的是"一个架次值多少"，而不是"无人机还能卸几个客户"。

## 5. 局限

- 能耗是线性代理（`alpha + beta × 载荷`），没有空气动力学项，也没有悬停与起降能耗。
- 参数（`ALPHA`、`BETA`、`E_D`、`P_MAX`）是设定的，没有针对具体机型标定，所以在 BETA 上做了扫描。
- 已发表启发式在 BETA > 0 时的"改善"只在它自己可行的子集上取均值，两组数不能直接比；
  这里把它当作"模型感知与否"的证据，而不是性能对比。
- 无人机电量在回收时视为复位（换电池假设），与主线一致；下面的主线实验覆盖了 K=1/2/3
  架，但参数仍没有针对具体机型或电池标定。
