# W8 补充实验：给卡车-无人机启发式加 LNS（大邻域搜索）

## 1. 动机

我的 V2 是一个构造式贪心：从最近邻卡车路线出发，反复卸载当前最划算的无人机架次，直到没有单个架次能再改进 makespan。它没有改进阶段，结果是该插入顺序下的一个局部最优；规模研究（`week06_largeN`）显示协同收益随 N 增大而坍缩，正是贪心缺改进算子的表现。

这一步在同一个 V2 解上加一个 **destroy-and-repair 的 LNS**，测它能带来多少提升。评估器仍用 W7 的 FSTSP 完成时间（单架串行无人机、会合约束），保证和贪心 V2、已发表基线同台比较。

## 2. 方法

- **状态**：`route`（卡车骨干，无人机服务的顾客不在其中）+ `drone_trips`（每个 `(起降点, 顾客元组, 回收点)`）。
- **毁坏**：随机移除 q 个顾客 / 移除卡车边际节省最大的 q 个顾客 / 移除一整个无人机架次。
- **修复**：每次把被移除顾客按 makespan 最小的方式重新插入——① 卡车路线最佳位置；② 单顾客架次；③ 与另一个待插入顾客拼成一个架次。起降点只在顾客最近的若干节点里枚举。
- **接受**：模拟退火（以 `exp(-Δ/T)` 接受更差解），保留历史最优。
- **确定性**：每个算例一个由算例种子派生的 RNG，迭代预算固定（8:300 / 12:300 / 16:300 / 20:400 / 30:250 / 50:150），同种子重跑结果一致。

## 3. 结果

10 个种子×6 个规模（N=8/12/16/20/30/50），共 60 个算例，同一评估器：

| 规模 | truck-only | V2 贪心 | 贪心+2-opt | 贪心+LNS | LNS vs 贪心 |
|---|---:|---:|---:|---:|---:|
| N=8  | 391.3 | 256.0 (−34.5%) | 247.7 | **222.2** (−43.2%) | **+12.51%** |
| N=12 | 579.4 | 412.1 (−28.9%) | 400.2 | **338.5** (−41.6%) | **+16.78%** |
| N=16 | 774.8 | 554.4 (−28.4%) | 533.9 | **471.0** (−39.2%) | **+13.29%** |
| N=20 | 1022.3 | 767.2 (−25.0%) | 746.3 | **594.4** (−41.9%) | **+21.32%** |
| N=30 | 1597.7 | 1270.1 (−20.5%) | 1220.6 | **1037.4** (−35.1%) | **+16.91%** |
| N=50 | 3114.1 | 2641.3 (−15.2%) | 2588.4 | **2188.4** (−29.7%) | **+16.59%** |

括号里是相对 truck-only 的 makespan 降幅（越大越好）。逐算例平均运行时间 0.15–6.1 s（单机，随规模上升）。

图：`figures/lns_vs_greedy.png`（左：各规模完成时间；右：相对贪心的提升）。

## 4. 结论

- LNS 相对贪心 V2 的提升在**所有规模上都稳定在 +12.5%~+21.3%**，且这不是噪声：配对 Wilcoxon 符号秩检验整体 **p = 1.7×10⁻¹⁰**，每个规模单独也都在 0.05 水平显著（见 `stat_tests.csv`）。
- LNS 明显**缓冲了规模衰减**：贪心相对 truck-only 的降幅从 N=8 的 34.5% 掉到 N=50 的 15.2%，而 LNS 从 43.1% 只掉到 29.5%；N=50 时 LNS 仍有 29.5% 的收益。
- 对照之下，只对卡车路线做 intra-route 2-opt 只带来约 2%~3.2% 的提升。这说明增益主要来自**重新分配无人机任务与整体结构**，不是路线微调——和 W7 消融里"多顾客能力才是主增益"的结论一致。
- 之前列的"贪心无局部搜索"这一局限，现在有了一个真的改进算子（LNS）来补，而不是只列在后续任务里。

## 5. 局限

- 仍是**单架无人机**、FSTSP 完成时间评估器（不含时间窗/电量）；LNS 的收益是在这个设定下测的。
- 算例仍是随机几何生成的合成算例，未接入领域标准的 FSTSP 实例集；N=100 未测（LNS 单算例已需约 5 s，更大规模需要先做候选剪枝/并行）。
- LNS 的参数（迭代数、毁坏规模、退火温度）是固定选的一组，没有做敏感性扫描。
