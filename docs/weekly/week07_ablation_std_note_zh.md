# 核心消融的标准算例复跑（Solomon 拓扑）

> 写于 2026-09-13。这份说明补的是我列在局限里的一条：五配置消融原来只在随机几何上做过，
> "多顾客能力是主增益"这条归因有可能只是随机云形状的产物。这里把同一实验搬到官方
> Solomon 拓扑上重跑，看结论是否还成立。

## 1. 为什么做

随机几何生成的顾客点均匀落在圆环里，而真实算例有聚类、有沿路分布。归因实验如果只在
一种几何上做，"主增益源"就可能绑定在这种形状上。所以需要换一套坐标系、保持其它一切不变，
再看增益分解。

## 2. 怎么做的

- **启发式代码完全不动**：直接复用 `week07_improvement_ablation.my_v2_param` 与它的
  `CONFIGS`，五个配置（published / v2 / abl_cap1 / abl_notakeoff / imp_cap3）与评估器
  都和合成算例那次一样。改动只在实例来源。
- **实例**：官方 Solomon 的四个不同空间族——C101（聚类）、C201（聚类，时间窗更宽）、
  R101（均匀）、RC101（混合）。仓库里的 Solomon 文件在同一族前缀内共享坐标，所以"取前 n 个
  顾客"每个族只能给出一组点；我对每个族滑动顾客窗口（从第 1 / n+1 / 2n+1 个顾客开始取 n 个），
  得到 4 × 3 = 12 个不同的顾客集，再乘 4 个规模（N=8/12/16/20），共 **48 个实例**。
- **坐标处理**：平移到仓库为原点，并缩放到与该规模下合成生成器相同的 RMS 半径
  （`fstsp_instances.make_solomon_fstsp(name, n, start)`）；卡车/无人机速度、服务时间、
  航程等模型常量都不变。

## 3. 结果

主要对比（每个规模 12 个实例的均值，括号内是相对 truck-only 的改善）：

| 规模 | truck-only | published | V2（我的） | abl_cap1 | abl_notakeoff | imp_cap3 |
|---|---:|---:|---:|---:|---:|---:|
| N=8  | 260.2 | 214.8 (17.3%) | **192.0 (25.4%)** | 214.8 (17.3%) | 197.1 (23.4%) | 171.4 (33.1%) |
| N=12 | 402.6 | 336.3 (15.8%) | **304.8 (23.0%)** | 336.3 (15.8%) | 313.2 (21.1%) | 291.6 (26.9%) |
| N=16 | 570.3 | 485.6 (14.7%) | **426.5 (23.6%)** | 485.6 (14.7%) | 434.9 (22.3%) | 406.5 (28.3%) |
| N=20 | 713.7 | 616.5 (12.8%) | **553.7 (21.1%)** | 616.5 (12.8%) | 565.3 (19.3%) | 517.7 (26.2%) |

增益分解（相对 truck-only 的百分点贡献）：

| 规模 | 多顾客能力 | 多次起降 | cap3 |
|---|---:|---:|---:|
| N=8  | **+8.1** | +2.0 | +7.7 |
| N=12 | **+7.2** | +1.9 | +3.9 |
| N=16 | **+8.9** | +1.3 | +4.7 |
| N=20 | **+8.3** | +1.8 | +5.1 |

与合成算例同项对照（同一套代码、同一评估器）：

| 规模 | 合成：多顾客 / 多次起降 / cap3 | 标准：多顾客 / 多次起降 / cap3 |
|---|---|---|
| N=8  | 10.6 / 2.4 / 4.0 | 8.1 / 2.0 / 7.7 |
| N=12 | 10.2 / 3.5 / 0.6 | 7.2 / 1.9 / 3.9 |
| N=16 | 12.1 / 4.4 / 8.9 | 8.9 / 1.3 / 4.7 |
| N=20 | 8.6 / 2.2 / 2.4 | 8.3 / 1.8 / 5.1 |

按空间族看多顾客能力的增益（各规模、各窗口的均值）：C101 **5.7pp**、C201 **5.8pp**、
R101 **14.1pp**、RC101 **6.9pp**。

## 4. 结论

1. **主增益源在两种几何上一致**：标准算例上多顾客能力贡献 **+7.2 ~ 8.9pp**，是三项里最大的一项；
   合成算例上是 +8.6 ~ 12.1pp。多次起降在标准算例上更小（**+1.3 ~ 2.0pp**，合成 +2.2 ~ 4.4pp）。
   "让无人机一次顺路服务多个客户"这条归因不是我挑的几何造成的。
2. **sanity check 仍然成立**：`abl_cap1`（我的框架 + 每架次 1 个顾客）在全部 48 个实例上
   与 published 的 makespan 逐个相等，说明"我的方法"和"已发表基线"之间确实只差多顾客能力这一项。
3. **V2 相对已发表基线的优势在标准拓扑上依然存在**：相对 truck-only，V2 是 21.1 ~ 23.6%，
   published 是 12.8 ~ 15.8%。
4. **增益大小依赖空间分布**：均匀分布的 R101 上多顾客能力值 14.1pp，聚类的 C101/C201 上只有
   5.7/5.8pp。聚类算例里远端点少，无人机一趟能顺路覆盖的"绕路"更少。

## 5. 局限

- 这条线走的是 FSTSP 评估器，**不含时间窗与电量**；电量与时间窗下的同类消融在 V3 那条线上，
  但 V3 目前没有做五配置分解。
- "标准算例"指**坐标来自官方 Solomon 文件**，但仍是"取 n 个顾客 + 缩放到合成半径"的派生实例，
  不是官方 FSTSP 算例本身（论文原始算例见 `docs/weekly/week08_mc_benchmark_note_zh.md`）。
- 只有 4 个不同的空间族；同一族的三组顾客窗口共享同一空间形态，独立性有限。
- 这里只报告相对 truck-only 的改善，绝对数值离最优仍有距离（精确最优性见 `docs/weekly/week08_exact_gap_note_zh.md`）。
