# V3（电动卡车 + 无人机 + 充电 + 时间窗）上的核心消融

> 写于 2026-09-13。这份说明补齐核心消融的第三个设定：week07 的消融跑在 FSTSP 评估器上
> （卡车无限续航、无时间窗），week07_ablation_std 把它换到标准 Solomon 拓扑，两者都还没有
> 电量与时间窗。V3 才是贴近 EVRP-TW 的设定，所以我在这里再做一次同样的分解。

## 1. 为什么做

FSTSP 设定里卡车的唯一约束是距离；V3 里卡车有电池、电量不足要绕到充电站满充、
客户还有时间窗。"多顾客能力是主增益"这条归因在电量与时间窗下是否还成立，需要单独验证：
电量会改变"卸掉一个客户"值与不值，时间窗会惩罚任何让卡车晚到的安排。

## 2. 怎么做的

- 复用 `v3_ev_collab.v3_greedy`，只给它加了两个开关：`max_cust`（每架次顾客数 1/2/3）
  与 `multi_takeoff`（同一停靠点能否服务多个架次）。这两个开关是**行为保持**的：
  `max_cust=2, multi_takeoff=True` 逐实例复现了 `v3_ev_collab.py` 已提交的结果
  （种子 20260720 下 n=8/12/16/20 分别为 240.5 / 374.4 / 815.0 / 1051.8）。
- 四个配置，锚点是 V1（纯电卡车，无无人机）：

  | 配置 | 每架次顾客数 | 停靠点复用 |
  |---|---:|---|
  | cap1 | 1 | 可以 |
  | v2 | ≤ 2 | 可以 |
  | notakeoff | ≤ 2 | 不可以（一个停靠点只服务一个架次） |
  | cap3 | ≤ 3 | 可以 |

- 规模 8/12/16/20，种子 20260720–20260729（10 个），共 40 个算例，与 `v3_ev_collab.py` 同批种子。
- 每个配置优化的都是 V3 贪心用的同一个罚目标（makespan + 1000 × 时间窗违例），
  所以结果里 makespan 与违例数一起报。
- 自检：空架次时 V3 评估器必须在 makespan、时间窗违例、充电次数三项上逐实例等于
  week06 的纯电路线，40/40 通过。

## 3. 结果

每个规模 10 个种子的均值，括号内是相对 V1 的 makespan 改善：

| 规模 | V1（纯电） | cap1 | v2 | notakeoff | cap3 |
|---|---:|---:|---:|---:|---:|
| N=8  | 485.8 | 338.1 (30.0%) | **257.8 (46.4%)** | 312.9 (35.4%) | 224.4 (53.6%) |
| N=12 | 694.7 | 550.9 (20.7%) | **415.1 (40.1%)** | 515.2 (26.1%) | 370.7 (46.4%) |
| N=16 | 975.9 | 719.8 (26.1%) | **628.7 (35.6%)** | 724.0 (25.9%) | 679.3 (30.2%) |
| N=20 | 1283.6 | 944.6 (26.2%) | **918.9 (27.9%)** | 1084.8 (15.2%) | 884.6 (30.7%) |

增益分解（相对 V1 改善的百分点贡献）：

| 规模 | 多顾客能力（v2−cap1） | 停靠点复用（v2−notakeoff） | cap3（cap3−v2） |
|---|---:|---:|---:|
| N=8  | **+16.4** | +11.0 | +7.2 |
| N=12 | **+19.4** | +14.0 | +6.3 |
| N=16 | +9.5 | +9.7 | −5.4 |
| N=20 | +1.7 | **+12.7** | +2.8 |

时间窗违例（均值）：V1 为 2.4 / 6.0 / 9.6 / 13.5，v2 为 0.0 / 1.9 / 6.0 / 9.7，
四个无人机配置全部 100% 能量可行。

配对 Wilcoxon（40 对，全部规模合并；平均差为负表示前者 makespan 更小）：

| 对比 | n | 平均差 | p |
|---|---:|---:|---:|
| v2 vs cap1（多顾客能力） | 40 | −83.2 | 9.4×10⁻⁵ |
| v2 vs notakeoff（停靠点复用） | 39 | −106.8 | 5.5×10⁻⁸ |
| cap3 vs v2（cap3） | 40 | −15.4 | 0.105（不显著） |

图：`figures/v3_ablation.png`。

## 4. 结论

1. **多顾客能力仍是最大的单项增益，但只在中小规模成立**：N=8/12 是 +16.4/+19.4pp，
   N=16 降到 +9.5pp，N=20 只剩 +1.7pp。整体配对检验仍显著（p=9.4×10⁻⁵）。
2. **"停靠点复用"在 V3 下从次增益变成了同等重要**：+11.0/+14.0/+9.7/+12.7pp，
   p=5.5×10⁻⁸；N≥16 时它甚至超过多顾客能力（N=20：+12.7pp 对 +1.7pp）。
   这与 FSTSP 设定下"多次起降只贡献 +2.2~4.4pp"明显不同。
3. **cap3 整体不显著**（p=0.105），N=16 时甚至为负（−5.4pp）。
4. 四个无人机配置都 100% 能量可行，时间窗违例也都低于 V1。

机制上说得通的部分：V3 的卡车要绕到充电站、还要满足时间窗，于是"把两个客户绑在一次
起飞里"既省了停靠、又让会合时刻更敏感；而"同一停靠点多次起降"可以在不改变卡车路线
形态的前提下多卸客户，因此在电量 + 时间窗下价值上升。也就是说，**这条归因是依赖模型
设定的**：在纯距离的 FSTSP 设定里多顾客能力一枝独秀，在 EVRP-TW 设定里它和停靠点复用
同等重要。这一点值得在报告里讲清楚，而不是只报 FSTSP 那一组数。

## 5. 局限

- 四个配置用的是同一个贪心，接受准则是罚目标；cap3 的负结果有一部分是贪心短视——
  一次吃掉 3 个客户的架次会锁住起降点，后续没有更好的组合可用。
- 时间窗仍是罚项而非硬约束（模型口径见 `docs/reference/formal_model_zh.md`）。
- 只做了单架无人机；K>1 的情况见 `docs/weekly/v3_ev_collab_note_zh.md`。
- 规模只到 N=20，没有再往大规模推。
