# V3（电动卡车 + 无人机 + 充电 + 时间窗）上的核心消融

> 写于 2026-09-13。这份说明补齐核心消融的第三个设定：week07 的消融跑在 FSTSP 评估器上
> （卡车无限续航、无时间窗），week07_ablation_std 把它换到标准 Solomon 拓扑，两者都还没有
> 电量与时间窗。V3 才是贴近 EVRP-TW 的设定，所以我在这里再做一次同样的分解。

## 1. 为什么做

FSTSP 设定里卡车的唯一约束是距离；V3 里卡车有电池、电量不足要绕到充电站满充、
客户还有时间窗。"多顾客能力是主增益"这条归因在电量与时间窗下是否还成立，需要单独验证：
电量会改变"卸掉一个客户"值与不值，时间窗会惩罚任何让卡车晚到的安排。

## 2. 怎么做的

- 复用 `v3_ev_collab.v3_greedy`，只给它加了两个开关：`max_cust`（每架次顾客数 1/2/3）
  与 `multi_takeoff`（同一停靠点能否服务多个架次）。这两个开关是**行为保持**的：
  `max_cust=2, multi_takeoff=True` 复现同一套评估器下的基准解。
- 四个配置，锚点是 V1（纯电卡车，无无人机）：

  | 配置 | 每架次顾客数 | 停靠点复用 |
  |---|---:|---|
  | cap1 | 1 | 可以 |
  | v2 | ≤ 2 | 可以 |
  | notakeoff | ≤ 2 | 不可以（一个停靠点只服务一个架次） |
  | cap3 | ≤ 3 | 可以 |

- 规模 8/12/16/20，种子 20260720–20260729（10 个），共 40 个算例。
- 每个配置优化的都是 V3 贪心用的同一个罚目标（makespan + 1000 × 时间窗违例），
  所以结果里 makespan 与违例数一起报。
- 自检：空架次时 V3 评估器必须在 makespan、时间窗违例、充电次数三项上逐实例等于
  week06 的纯电路线，40/40 通过。

## 3. 结果

每个规模 10 个种子的均值，括号内是相对 V1 的 makespan 改善：

| 规模 | V1（纯电） | cap1 | v2 | notakeoff | cap3 |
|---|---:|---:|---:|---:|---:|
| N=8  | 485.8 | 353.2 (26.7%) | **293.6 (39.2%)** | 319.1 (34.2%) | 263.5 (45.7%) |
| N=12 | 694.7 | 576.9 (16.9%) | **517.4 (25.4%)** | 532.1 (23.3%) | 480.4 (31.2%) |
| N=16 | 975.9 | 799.8 (18.1%) | **693.9 (29.0%)** | 744.7 (23.7%) | 755.4 (22.3%) |
| N=20 | 1283.6 | 1037.9 (19.1%) | 1069.0 (16.3%) | 1095.1 (14.4%) | **1003.2 (21.6%)** |

增益分解（相对 V1 改善的百分点贡献）：

| 规模 | 多顾客能力（v2−cap1） | 停靠点复用（v2−notakeoff） | cap3（cap3−v2） |
|---|---:|---:|---:|
| N=8  | **+12.5** | +5.0 | +6.5 |
| N=12 | **+8.5** | +2.1 | +5.8 |
| N=16 | **+10.9** | +5.3 | −6.7 |
| N=20 | −2.8 | +1.9 | +5.3 |

时间窗违例（均值）：V1 为 2.4 / 6.0 / 9.6 / 13.5，v2 为 0.0 / 3.2 / 6.3 / 10.5；
四个无人机配置全部 100% 能量可行。

配对 Wilcoxon（40 对，全部规模合并；平均差为负表示前者 makespan 更小）：

| 对比 | n | 平均差 | p |
|---|---:|---:|---:|
| v2 vs cap1（多顾客能力） | 37 | −52.4 | 5.3×10⁻³ |
| v2 vs notakeoff（停靠点复用） | 20 | −58.6 | 2.4×10⁻⁴ |
| cap3 vs v2（cap3） | 38 | −18.8 | 0.139（不显著） |

图：`figures/v3_ablation.png`。

## 4. 结论

1. **多顾客能力在电动 + 时间窗设定下仍是最大的单项增益**：N=8/12/16 分别是
   +12.5 / +8.5 / +10.9pp，整体配对检验显著（p=5.3×10⁻³）。到 N=20 转为 −2.8pp——
   电量与时间窗把"可卸载的窗口"压得很窄，贪心在 20 个客户上已经找不到稳定的多顾客组合。
2. **停靠点复用是次增益**：+5.0 / +2.1 / +5.3 / +1.9pp（p=2.4×10⁻⁴）。注意 40 对里只有
   20 对非零——多数算例上"允许复用"与"不允许复用"给出同一解，说明这条开关只在部分几何上起作用。
3. **cap3 整体不显著**（p=0.139），N=16 时甚至为负（−6.7pp）：三顾客架次在电量与时间窗下
   更难同时满足航程、会合与时间窗。
4. 四个无人机配置都 100% 能量可行，时间窗违例也都低于 V1。

把三个设定放在一起看，归因是**一致的**：多顾客能力在 FSTSP 设定（合成 +8.6~12.1pp、
标准算例 +7.2~8.9pp）和电动 + 时间窗设定（+8.5~12.5pp）下都是最大的一项；差别在于 V3 下
它到 N=20 就失去优势，而 FSTSP 设定到 N=20 仍有 +8.6pp。也就是说"多顾客能力是主增益源"这条
结论在更严的模型下依然成立，只是适用规模更小。

## 5. 局限

- 四个配置用的是同一个贪心，接受准则是罚目标；N=20 上多顾客能力的负值有一部分是贪心短视——
  一次吃掉 2 个顾客的架次会锁住起降点，后续没有更好的组合可用。
- 时间窗仍是罚项而非硬约束（模型口径见 `docs/reference/formal_model_zh.md`）。
- 只做了单架无人机；K>1 的情况见 `docs/weekly/v3_ev_collab_note_zh.md`。
- 规模只到 N=20，没有再往大规模推。
