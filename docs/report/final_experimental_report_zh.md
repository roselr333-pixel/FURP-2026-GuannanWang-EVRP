# 电动卡车与无人机协同的路径优化：复现、改进与适用边界

FURP 2026 研究型项目最终实验报告 · Guannan Wang
仓库：https://github.com/roselr333-pixel/FURP-2026-GuannanWang-EVRP

## 摘要

本项目研究**电动卡车 + 无人机 + 时间窗 + 充电站**的协同路径问题：无人机从卡车经过的节点起飞，服务 1–2 位顾客后在卡车后续节点回收，目标是最小化卡车带着无人机回到仓库的完成时间。我在同一套物理评估器上复现了 Murray & Chu (2015) 的 FSTSP 与 Schneider et al. (2014) 的 E-VRPTW，再把"一架次服务多顾客"与"同一停靠点多次起降"两项改进接进四类约束并存的模型。40 个合成算例上，该改进相对纯卡车基线降低 24.8%–34.5%，相对已发表启发式再短 10.2%–14.2%；五配置消融显示主增益来自多顾客能力（+8.6 ~ +12.1 个百分点，配对 Wilcoxon p = 2.4×10⁻⁷），满足"复现 + ≥10% 创新"的要求。边界同样清楚：规模从 N=30 到 N=100 时协同收益从 8.6% 衰减到 0.5%，N=100 时电量与载重同时不可行。用 CP-SAT 求精确最优，只有 n=8 证明最优（LNS 离最优 16.5%），n ≥ 10 的对偶界为 0。报告里所有数字都可由 `run_all.py` 与固定种子重跑。

## 1 问题定义与模型

**决策**：卡车路线的访问次序；每位顾客由卡车还是无人机服务；每个架次的起飞点、顾客序列与回收点；（K > 1 时）架次到无人机的分配。**目标**：最小化完成时间 T_end，即卡车带着无人机回到仓库的时刻。评估器按"先累加卡车行驶与服务时间，再按起飞顺序让卡车在回收点等待无人机落地"的递推计算。

| 变体 | 卡车 | 无人机 | 时间窗 |
|---|---|---|---|
| V0 | 无电池限制 | 无 | 计罚 |
| V1 | 电池 + 充电站 | 无 | 计罚 |
| V2 | 电池 + 充电站 | 1 架 | 计罚 |
| V3 | 电池 + 充电站 | K = 1/2/3 架 | 计罚 |
| FSTSP 模式 | 视为无限续航 | 1 或 K 架 | 不计罚 |

| 约束 | 内容 | 处理 |
|---|---|---|
| C1 | 每位顾客恰好被服务一次 | 硬 |
| C2 / C3 | 架次飞行距离 ≤ R；起飞点在回收点之前 | 硬 |
| C4 | 无人机串行，起飞时该无人机必须已回到卡车 | 硬 |
| C5 | 卡车在回收点等待无人机落地 | 硬 |
| C6 | 电量按 ρ·d 消耗，不足时绕最近充电站满充；满电仍不够则判不可行 | 硬 + 贪心修复 |
| C7 | 卡车路线承载需求 ≤ CAP = 1000 | 硬（已启用） |
| C8 | 顾客时间窗 | **软**：早到等待、晚到计数，不拒绝解 |
| C9 | 无人机载荷上限与随载荷增长的能耗预算 | 可选硬（默认关闭） |

常量：v_T = 1、v_D = 2、服务时间 10、满充 40、ρ = 1、Q = 250、R = 160、CAP = 1000、每架次 ≤ 3 顾客（主线 1–2）。时间窗做成软约束是有意的：做成硬约束后大规模算例会大量无解，我就看不到"规模变大时协同如何失效"。

## 2 复现与创新

**(1) Murray & Chu (2015) FSTSP。** 在论文公开的 36 个 10 顾客原始算例上复现其物理模型与插入启发式（每架次 1 顾客、单无人机、串行、回收点等待）。严格按其定义运行时，我的 LNS 达到 LNS/OFV = 0.924，即比文献 objective 好约 7.6%；相对同算例的纯卡车 TSP 降低 22.3%。

**(2) Schneider et al. (2014) E-VRPTW。** 把 92 个原始实例（真实坐标、时间窗、充电站、论文电池参数）转成我的实例字典，用同一套评估器复核"合成结论能否外推"；另写一个面向该算例集的求解器直接比 BKS。18 个有 BKS 的实例上，平均距离差距从构造阶段的 +52.7% 收到加局部搜索后的 **+21.3%**，平均车辆数 3.28（BKS 2.06）；其中 3 个实例距离与 BKS 完全一致，2 个小实例甚至更短。剩余差距集中在 100 顾客紧时间窗实例的车队装填。

**(3) 我的创新。** 把"一架次最多 3 位顾客"与"同一停靠点可多次起降"引入上述模型，并与电池、充电站、时间窗、载重、多无人机整合。五配置消融里，"每架次 1 顾客"的配置与已发表启发式**逐实例相等**，而加入多顾客后相对已发表方法短 10.2%–14.2%，这正是 ≥10% 创新的直接证据。

## 3 方法

**统一物理评估器。** 所有方法（我的启发式、已发表启发式、CP-SAT）都调用同一个评估器算完成时间，不可行返回 inf，保证比较同台。它修过两类缺陷：一是把单架无人机当成可以并行执行多个架次，二是发射时没有检查该无人机是否已经回到卡车；修复后所有依赖实验重跑，W6 主线的收益从 42%–55% 下调到 16%–34%。

**V2 构造式贪心（主线）。** 最近邻生成卡车路线，反复枚举"把某段区间内的若干顾客改由无人机服务"的候选架次（1–3 位顾客、任意起降节点对），只接受严格改善且物理可行的移动，直到无法改进。

**改进阶段。** LNS 用 destroy-and-repair（随机 / 最差 / 整趟毁坏 + 卡车插入 / 单顾客 / 双顾客修复 + 模拟退火接受）。后来发现其毁坏规模上限只有 min(8, n/4)（n=10 时只能毁坏 2 位顾客），于是写了 ALNS：5 个毁坏算子（随机、最差、关联、路线片段、整个架次）+ regret-2 修复 + max(2, 0.35n) 毁坏规模 + 自适应算子权重。

**V3 与多无人机。** V3 把电池、充电站、时间窗叠回协同模型：路线只列顾客，充电绕行由评估器动态插入（最近站满充）；无人机 K 架同构、各自串行。多无人机在 FSTSP 模式下扩展，并用分支定界加下界证书检验"架次到无人机"的调度。

**精确最优。** CP-SAT 模型用弧变量 + MTZ 位序表示卡车路线，显式枚举候选架次，用"离开节点时无人机是否在空中"的 0/1 状态编码串行约束，时间取 1/100 整数网格。两项独立验证：航程置 0 时退化为纯卡车 TSP（与 Held-Karp 一致）；n=5 时与全空间暴力枚举一致。求解时把启发式的最好计划同时作为目标上界与提示（热启动）。

**三条纯卡车基线。** OR-Tools（10 秒/实例）、PyVRP 0.14.0（固定种子）、自写 GA（排列编码 + I1 解码 + OX 交叉，5 种子）。它们最小化的是距离，而 V1/V2/V3 最小化完成时间，所以只用于建立参照系，不用于协同模型的对比。

## 4 实验设置

**算例**：合成环形算例（N = 8–100）；官方 Solomon 56 实例（三条基线）；Solomon 派生的 FSTSP 算例（消融与多无人机）；Murray & Chu (2015) 原始 36 算例；Schneider (2014) 原始 92 实例。

**种子与指标**：GA 用 20260717 起 5 个种子；week06/07/08 用 20260720 起的连续种子（多规模 10 个、大规模与精确研究 5 个）。每项实验都报目标值、可行性（可行率与物理有效比例）、违约（时间窗、电量、载重、会合否决）与运行时间；显著性用配对 Wilcoxon 符号秩检验。

**复现**：`python run_all.py`（47 步，含全部实验与图，约 2.5–3 小时）；`python -m pytest tests/ -q`（167 个回归测试，约 35 秒）。CSV 不入库、可用种子重新生成，日志入仓且全部 UTF-8，参数与种子逐项记在 `docs/reference/configs_and_parameters.md`。

## 5 结果

**5.1 三条纯卡车基线（56 个官方 Solomon 实例，vs BKS）**：PyVRP 平均 gap −3.0%（逐实例稳定）、OR-Tools +7.2%（10 秒预算，重跑 7.2%–8.1%）、自写 GA +36.6% ± 15.8%。PyVRP 在六个族上全部优于 BKS，说明现代求解器可以超过历史最好已知解；这张表只用来建立参照系。

**5.2 主线 V0/V1/V2（4 规模 × 10 种子）与五配置消融（40 算例）**：

| 规模 | V0 纯卡车 | V1 纯电 | **V2 协同** | V2 vs V1 | 卸载率 | V2 时间窗违约（V1） | 可行/有效 |
|---|---:|---:|---:|---:|---:|---:|---|
| N=8 | 434.7 | 485.8 | **324.2** | **−33.6%** | 31.2% | 0.5（2.4） | 100% |
| N=12 | 614.4 | 694.7 | **525.4** | **−24.5%** | 21.7% | 3.2（6.0） | 100% |
| N=16 | 816.6 | 975.9 | **783.9** | **−19.6%** | 18.1% | 6.7（9.6） | 100% |
| N=20 | 1080.1 | 1283.6 | **1078.4** | **−15.6%** | 14.5% | 10.7（13.5） | 100% |

| 消融（相对纯卡车） | N=8 | N=12 | N=16 | N=20 |
|---|---:|---:|---:|---:|
| 已发表启发式（每架次 1 顾客） | 23.9% | 18.8% | 16.6% | 16.2% |
| 我的 V2（多顾客 + 多次起降） | **34.5%** | **29.0%** | **28.7%** | **24.8%** |
| 增益分解：多顾客 / 多次起降（pp） | +10.6 / +2.4 | +10.2 / +3.5 | +12.1 / +4.4 | +8.6 / +2.2 |

电池让纯卡车慢 11.8%–19.5%，这正是无人机的机会；会合否决次数从 N=8 的约 512 次涨到 N=20 的 21689 次，是规模衰减的直接机制。时间窗在搜索里是软约束，所以违约没有降到 0，但比 V1 少一半。

**5.3 标准算例与规模边界**：把模型搬到 Schneider 的真实坐标/时间窗/电池上，收益反而更大——N=8/12/16/20 为 **54.8 / 48.8 / 43.7 / 41.0%**（合成参照 34.5 / 29.0 / 28.7 / 24.8%），每实例超时顾客下降 4.2–9.3，说明合成算例的结论偏保守；用论文自己的载重 C = 200 时，V2 可行率为 100/100/58/50%，换回 CAP=1000 则 96/96 全可行。规模推到 N=30/50/100 时，协同收益为 **8.6% / 3.4% / 0.5%**，卸载率 11.3% / 5.2% / 2.8%；N=100 的 V1/V2 能量可行率为 0/5、平均 88.6/100 顾客超时，有效协同区间约 N ≤ 30。

**5.4 改进阶段**：LNS 相对贪心在所有规模稳定 +12.5%–+21.3%（配对 Wilcoxon p = 1.7×10⁻¹⁰），并把 N=50 的协同收益从 15.2% 抬到 29.5%；只做卡车路线 2-opt 只有 2.5%–3.2%，说明增益来自无人机任务重分配。ALNS 把毁坏规模从 min(8, n/4) 放大后，n=8–16 上再短 2.7%–12.2%（平均 +6.3%）；但**自适应权重没有起作用**——同预算同种子下冻结权重在 n=8/12/16 上更好，增益来自算子集合与毁坏规模。

**5.5 V3、多无人机与载重**：V3（电动 + 时间窗 + K 架）相对纯电卡车降低 **33.5%–52.4%（K=1）**、最高 **72.5%（K=3）**，并把时间窗违约与充电绕行大部分消掉；多无人机在 FSTSP 设定下 K=1→3 把 N=8 的收益从 43.1% 抬到 69.6%、N=50 从 29.5% 抬到 38.1%，标准算例 K=1→5 达到 46.8%–71.4%，而"架次到无人机"的调度在 64/64 个配置上与下界相等（可证明最优）。载重方面：声明的 CAP=1000 在 N ≤ 50 不 binding（所以主线重跑逐位不变），一旦 binding（cap=600 的 N=100、cap=400 的 N ≥ 50）单架无人机修不回来，留在卡车上的需求从 64.7% 升到 97.2%。

**5.6 能耗闸门与精确最优**：给无人机加"载荷上限 + 随载荷增长的能耗预算"后（β = 0 时精确退化为原航程约束），主线收益仍在（V3 K=1 33.5%–53.0%、K=3 最高 72.4%），代价是 makespan 多 1.5%–8.1%；但它吃掉了"多一架"的边际价值（N ≥ 16 时 K=1→3 少赚 5–10 pp），而不感知能耗的已发表启发式只有 42%–48% 的计划能量可行。精确最优方面：n=8 的 5 个算例**全部证明最优**（贪心离最优 +31.2%、LNS +16.5%）；n=10–16 只能给可行解，认证对偶界全是 0（300 秒探针在 n=10 上也只有 27.6 对 incumbent 217），而且 **CP-SAT 自己的可行解比我的 LNS 还好 8.8%–17.5%**——瓶颈既在证明也在搜索。

## 6 失败与违约分析

`docs/reference/failure_cases_master.md` 收录 13 条约束级案例，按 7 个字段写（算例 / 求解器 / 目标值 / 可行性 / 违反的约束 / 从哪一步不可行 / 下一步）。三个代表：

- **会合约束否决（N=20）**：最终解可行，但枚举中被"无人机还没回到卡车"否决的候选架次达 21689 次/算例；N=50 涨到 101 万次。这是规模衰减的直接原因，也是 LNS/多无人机要缓解的对象。
- **航程太小（R=40）**：不违反硬约束，但候选架次几乎全部超出行程，协同收益从 24.5% 掉到接近 0；解决方式是把 R 当设计变量扫描（R ≥ 160 后饱和）。
- **评估器把单架无人机当并行（已修）**：一个架次内部嵌套另一个架次时，评估器仍按顺序算时间，15 个实例里有 14 个被赋予偏小的 makespan（早期文档里的 56.7%–87.8% 降幅就来自这里）。修复后多个评估器都强制"起飞时无人机必须在卡车上"，全部实验重跑，W6 主线的收益从 42%–55% 下调到 16%–34%。

另有一处容易误读的充电细节：**V2 的充电次数与 V1 完全相同**（0.9/1.3/2.1/2.9），充电时间占比从 7.4%–9.0% 升到 10% 左右完全来自分母变小，不是 V2 充得更多。

## 7 局限与下一步

**局限**：精确下界只到 n=8（n ≥ 10 的对偶界为 0，那些 gap 只是下界）；时间窗是软约束，不保证硬可行；Schneider 的算例是为车队设计的，我只用一辆卡车跑，比较的是相对价值；车队装填偏弱（平均 3.28 车对 BKS 2.06）；充电只有"最近站满充"，没有部分充电；无人机能耗参数是假设值，没有针对机型标定；标准算例规模未超过 50。

**下一步**：① 对架次集合做集合划分 LP 加列生成（或 MILP 根节点下界），把 n ≥ 10 的 gap 变成真正的界；② 把 ALNS 接到 V3 上（目前它只在无电池无时间窗的 FSTSP 模型上）；③ 做硬时间窗版本；④ 改进车队装填；⑤ 补部分充电与能耗标定、接入更大规模的标准算例；⑥ 完成海报、演示视频与幻灯片（占评分 30%）。

## 8 结论

1. **统一、可复现的评估器是前提**：同一算例、同一目标、只动一个旋钮，才让复现两篇论文、五配置消融、多无人机与精确最优之间能够互相印证；评估器修缺陷后数字变差但结论更可信。
2. **核心改进有效且可归因**：多顾客架次是主增益（+8.6 ~ +12.1 pp，p = 2.4×10⁻⁷），相对已发表启发式短 10.2%–14.2%，满足 ≥10% 创新的要求。
3. **结论可外推、边界清楚**：真实数据上的收益比合成更大（41.0%–54.8% 对 24.8%–34.5%）；有效区间约 N ≤ 30，N=100 时电量与载重同时失效。
4. **搜索一侧还有空间**：LNS 相对贪心 +12.5%–+21.3%，ALNS 再 +2.7%–+12.2%；但 n=8 上 LNS 离已证明最优仍有 16.5%，n ≥ 10 时 CP-SAT 的可行解比我的启发式更好——方法有效，但没有接近最优。
