# 深度分析：卡车-无人机协同 EVRP-TW 的"为何有效、何时有效"

> 这份分析把前面分散的结果（5 配置消融、参数敏感性、多目标权衡、三基线对比、失败案例）
> 串成一条完整的结论链：协作增益从哪来、在什么场景下划算、方法自身的边界在哪。
> 所有数据均来自本项目自己的实验，不引用任何同学的报告结构或概念框架。

---

## 1. 一条主线：协作增益的主源是"多顾客能力"，不是"会合次数"

这是整个项目最该讲清的一点，由两个**相互独立**的实验互相印证：

- **受控消融**（week07，5 配置同台）：在固定"无人机可多次起降"的前提下，
  把"每架次最多服务 1 个客户"放宽到"2–3 个"，带来的增益是
  **+6.6 ~ 17.7 个百分点**；而"允许多次起降"本身只贡献 **+4.1 ~ 7.3 个百分点**。
  也就是说，让无人机**一次飞出去顺路服务多个客户**，才是增益的主来源。
- **参数敏感性**（week06，扫 K = 每架次服务客户数）：K 从 1 增到 3，
  协同收益从 **25.3% 升到 56.5%**，方向与消融完全一致。

两个实验用不同的实例集、不同的角度，指向同一个结论——这说明结论**稳**，不是某次运行的偶然。比报一个好看的最终数字更重要的是，用受控实验把增益的机制讲清楚。

---

## 2. 适用区间：协作在"客户分散、续航充足、规模中等"时最划算

把四个物理参数的扫描结果放在一起，可以刻画协同收益的**适用边界**
（均为 5 种子均值，误差带见 `figures/sensitivity_panels.png`）：

| 参数 | 扫描 | 协同收益变化 | 解读 |
|---|---|---|---|
| 电池容量 Q | 120 → 500 | 55.8% → 47.1% | 电池越大，卡车越"自给"，无人机价值被稀释 |
| **无人机续航 R** | 60 → 200 | **15.5% → 50.5%**（160 后饱和） | 续航 < 160 时是**真实瓶颈**，绑定收益 |
| 每架次客户数 K | 1 → 3 | 25.3% → 56.5% | 与消融一致，多顾客能力是主增益 |
| 客户规模 N（距离维） | 8 → 30 | 63.8% → 35.3% | 距离维收益随规模稀释 |

**规模扩展（时长维，N=30/50/100，5 种子）**：V2 相对 V1 的 makespan 优势
27.6% → 12.1% → 2.3%，卸载率 62.0% → 42.8% → 23.4% 单调下降；N=100 时 V2 平均
71.4/100 顾客超时（TW 可行性崩溃，因贪心本不保证时间窗可行）。完整曲线见
`figures/largen_scale_decay.png`。

**综合结论**：卡车-无人机协同在"客户点分散、无人机续航不受限、问题规模中等"
时收益最高；当规模大到电池约束给卡车近乎一倍代价时，协同红利被摊薄（有效协同区间实质落在 N ≤ 50）。W8 的 LNS 在 N=50 上把协同收益从贪心的 17.6% 抬到 28.1%，减缓了这一衰减。
这是一个**有数据支撑的适用区间判断**，不是泛泛而谈"无人机有用"。

## 3. 多目标维度：V2 在"距离"和"时长"两轴同时占优 V1

同步式卡车-无人机模型里，距离和完成时长（makespan）天然存在权衡。
用加权和扫描（w ∈ {0, 0.25, 0.5, 0.75, 1.0}，5 种子）得到：

- 纯卡车 EV（V1）均值：(距离 486.4, 时长 622.4)
- 协同（V2）均值：(距离 215.2, 时长 415.7)
- 即距离 **−56%**、时长 **−33%**，**两个轴同时占优**，是真实的 Pareto 改善。

**说明**：这里用的是加权和标量化的贪心，不是完整 NSGA-II / Pareto 求解器，
给出的前沿是"粗"的。这是本方法的局限，不是卖点——下节会把它写进局限。

## 4. 与三条基线的关系：各自站什么位置（已整合到一张表）

把 OR-Tools、GA、PyVRP 三条"纯卡车 VRPTW"基线与 BKS 摆在一张表
（`baseline_consolidated.csv`，56 Solomon 实例）：

| 基线 | 相对 BKS 平均 gap | 角色 |
|---|---|---|
| **PyVRP**（领域标准开源） | **−3.0%** | 最强基线，社区公认求解器 |
| OR-Tools（商业求解器） | +7.2% | 主要对照基线 |
| GA（自写，5 种子均值） | +36.6% ± 15.8% | 自写元启发，性能弱于前两者 |

**说明**：我的 V2 是**协同启发式**，优化的是 makespan 驱动的同步目标，
其"距离"不直接与这些纯距离最小化基线比较。将它们并列，是为了说明
在标准卡车 VRPTW 上 PyVRP 能打到甚至略优于 BKS；本项目的增量在协同建模，
而非单目标距离优化。

## 5. 失败案例分析

17 条失败案例里最值得说的是：在 N=50 的密集算例上，**会合可行性否决次数达到
约 450 万次**。这说明同步会合约束（无人机必须回到卡车路径上的某点汇合）在
大规模下是主要瓶颈——恰恰印证了"同步模型"的现实代价，也解释了第 2 节里
"规模越大协同收益越被稀释"的现象。失败不是丢脸，它和敏感性结论**互相印证**，
共同划定了方法的适用边界。

## 6. 局限

- **贪心本身无局部搜索（W8 补上了 LNS）**：V2 跑完 2-opt 后处理，增益仅 0–1.76% —— 说明卸完远端客户后
  卡车路线已接近线性，路线微调几乎无效，增益来自"协同结构"。W8 加了 destroy-repair 的 LNS 后，相对贪心在各规模稳定提升
  **+9%~+12.6%**（Wilcoxon 整体 p=3.6×10⁻⁹），并缓冲了规模衰减（N=50 从 17.6% 抬到 28.1%）。
- **每架次限 2–3 个客户**：是简化也是边界，更大规模的多顾客服务需要更重的搜索。
- **仍为单架无人机**：LNS 及全部协同结果都在单架串行无人机下测得，多无人机留作扩展。
- **合成算例规模扩至 100，但有效协同区间落在 N ≤ 50**：未接入领域常用的标准大规模基准集（如 Murray & Chu 2015 基于 Solomon 派生的 FSTSP 算例，本项目 W7 已在其参数范围内复现）；N=100 时协同收益坍缩至 2.3%、V2 平均 71.4/100 顾客超时（TW 可行性崩溃），结论外推需谨慎。
- **未复现 MILP 下界**：基线对比用 BKS（文献最优）而非自证下界，绝对质量靠文献锚定。

---

## 7. 小结

不是方法更花哨（贪心框架没换），而是把结论串成了一条完整的链：

> 受控消融指出增益主源（多顾客能力）→ 敏感性在独立角度印证（K 扫描）→
> 四个参数刻画适用区间（客户分散/续航足/规模中）→ 规模扩展至 100 揭示协同坍缩与 TW 崩溃（有效区间 N≤50）→
> 多目标证明两轴占优 → 三基线定位 V2 的协同增量 → 失败案例与会合约束互相印证 →
> W8 的 LNS 补上改进阶段（+9~12.6%，缓冲规模衰减）→ 局限（规模边界 / 合成算例 / 单无人机）。

这条链让每一个结论都能被追到实验，而不是停留在"我觉得"。
